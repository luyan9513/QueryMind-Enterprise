# v0.9 生产候选分层评测设计

## 当前结论

Chinook r6 已通过 24 题开发门槛，但原题集分布不够支撑生产候选结论。v0.9 已完成两批扩展，目前为 50 题：easy/medium/hard = 17/22/11。第二批 18 题重点补过滤、日期过滤、时间序列、员工、销售、HAVING 和空值处理，`filtering` 已达到最低 5 题目标。目标仍不是凑满题数，而是建立可机器检查的 100 题分层准入和 3 次重复稳定性流程。

2026-08-04 决定暂时冻结在 50/100：先完成 v0.10 Run 状态、Trace、错误分类与 HITL 接口设计/实现，再补齐并冻结 100 题。原因是新运行时会改变过程事件、审批、恢复和在线指标的数据结构；现在继续扩题和跑模型，会产生重复迁移和不可比报告。暂停不等于取消 100 题目标。

## 本阶段范围

1. 新增版本化 benchmark admission profile，声明题数、难度、类别、业务域、SQL 标签、重复次数和质量门槛；
2. 新增只读检查命令，输出当前覆盖、缺口和是否满足准入，不调用模型、不连接数据库；
3. SQL Contract 支持“特征替代组”，例如 WHERE/HAVING 任一满足即可，修复 016 的实现绑定；
4. 先增加一批经过人工题意检查和参考 SQL 验真的问题，再分批扩到 100 题；
5. 100 题冻结后再运行每题 3 次的 S0/S3/S5，不用开发中题集反复刷模型。

## 生产候选门槛

- 题数不少于 100；
- 每题至少重复 3 次；
- 参考 SQL 可执行率 100%；
- Schema Recall ≥90%；
- 业务正确率 ≥80%；
- 错误执行率 ≤10%；
- 自动回答覆盖率 ≥85%；
- P95 Agent 延迟 ≤30 秒；
- 逐题业务正确性重复一致率 ≥85%；
- 数据集、数据库快照、Schema 快照、模型和温度必须可比。

这些门槛是本项目的生产候选标准，不代表开放世界所有问题的 100% 保证。

## 防止为分数写题

- 问题先由业务意图产生，再写参考 SQL；不从模型失败 SQL反推题面；
- 题面必须明确返回列、粒度、过滤、时间范围和并列规则；
- 参考 SQL 必须只读执行、结果非空，并通过结构合同；
- 同一业务意图的改写题不能重复计入主要题数；
- 题集冻结后才跑正式模型；修题必须升级版本并保留旧报告；
- AdventureWorks、Chinook 和未来数据源分别建 profile，不复用准确率。

## 恢复条件

满足以下条件后再继续扩到 100 题：

1. v0.10 Run/Step/Event 状态与错误码稳定；
2. 评测器能记录统一 Trace、恢复动作、审批和澄清事件；
3. 数据集冻结规则明确为开发/测试/保留集，建议比例 `60/20/20`；
4. 真实模型预算、停止规则和三次重复方案再次确认；
5. 新增题仍先做人审、参考 SQL 只读验真和结构合同检查。
