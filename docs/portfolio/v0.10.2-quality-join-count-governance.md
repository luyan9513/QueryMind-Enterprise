## 1. 结论

本阶段修复了一个可泛化的连接计数缺陷：Query Plan 已要求
`COUNT(DISTINCT ...)` 时，生成 SQL 不能退化为普通 `COUNT(...)`；Semantic
Contract 也不能豁免连接后的主键去重安全规则。目标用例 `ch_zh_044` 在最终代码上
连续三次达到业务正确率 100%、wrong-but-executed 0%。

但 100 题 Chinook S5 正式复测为 78% / 78% / 79%，三轮均值 78.33%，低于
80% 硬门槛；P95 和一致性也未过门槛。因此严格遵守阶段门禁，停止 P0-B，未执行
AdventureWorks 回归、Result Validation、Run/Event evidence linking 或平台扩张。

## 3. 最小实现

涉及本阶段最小缺陷修复的文件：

- `src/QueryMind/core/agent/query_plan.py`
  - 从计划和 SQL 中提取 `COUNT(DISTINCT column)`；
  - 同时保留 SQL alias 和物理表名，避免合法 alias 被误拒；
  - 当计划要求 DISTINCT 而 SQL 缺失时拒绝；
  - Semantic Contract 不再绕过连接主键的通用 fanout 安全检查。
- `tests/test_query_plan.py`
  - 新增“计划 DISTINCT 必须保留到 SQL”回归；
  - 新增“Semantic Contract 不能豁免连接主键去重安全”回归。

没有新建第二套 Context、Memory、Governance 或 Evaluation 框架，也没有引入
Reviewer、多 Agent、MCP、Skill、新方言或新依赖。
