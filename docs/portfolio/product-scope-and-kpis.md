# QueryMind Data Agent：业务范围与效果指标

状态：`v0.10 运行时已实现，生产化边界仍受限`。本文同时区分已落地能力、评测证据和未来生产指标。

## 一句话定位

QueryMind Data Agent 是面向企业销售与经营分析场景的**受治理数据问答 Agent**：用户用自然语言提出经营问题，系统在已授权的数据范围内检索 Schema 和业务口径、规划查询、生成并校验只读 SQL，并把答案、依据和风险一起返回。

它不承诺“任意数据库、任意问题都自动答对”。可兑现的保证是：

1. 已准入的数据源和问题范围，使用冻结题集报告准确率、覆盖率、错误执行率、延迟和成本；
2. 证据不足、口径不清或风险过高时，澄清、请求人工确认或拒绝执行；
3. 数据源、Schema、模型、Prompt、合同或治理规则变化后重新评测，旧分数不自动继承。

## 明确用户

| 用户 | 典型任务 | 最关心的结果 | 系统责任 |
| --- | --- | --- | --- |
| 销售/运营负责人 | 看收入趋势、客户结构、商品表现、异常变化 | 快速得到可信答案，不必自己写 SQL | 给出答案、查询范围、口径和风险提示 |
| 数据分析师 | 复核 SQL、维护指标口径、分析失败原因 | 减少重复取数，同时保留可审计性 | 展示 SQL、Schema/合同证据和运行轨迹 |
| 数据负责人/管理员 | 接入数据源、配置权限、批准高风险查询 | 不串库、不越权、不执行危险 SQL | 准入检查、RLS、审批策略、审计记录 |

首个产品闭环聚焦“销售与经营分析的只读取数”。写操作、自动修改业务数据、自由访问元数据和无人审批的敏感明细导出不在当前范围内。

## 核心业务流程

1. 用户提出经营问题，并选择或继承数据源。
2. 系统识别意图、业务域和风险；问题含糊时先澄清。
3. 系统检索当前数据源的 Schema 和已批准指标合同，生成结构化 Query Plan。
4. Agent 生成 SQL；确定性 Governance 校验只读、安全、Schema 证据、合同和 RLS。
5. 普通查询直接执行；高风险但允许的查询进入人工审批。
6. 系统验证结果结构与口径，返回答案、SQL、引用证据和执行状态。
7. 用户可反馈“正确、部分正确、错误”，反馈进入评测与根因闭环。

## 产品成功指标

### 离线准入指标

| 指标 | 说明 | 当前证据 | v0.10 后续准入方向 |
| --- | --- | --- | --- |
| 全题业务正确率 | 正确题数 / 全部冻结题目，拒答也进入分母 | Chinook v0.8 S5：20/24，83.33% | 按难度、业务域和题型分别设门槛，不只看总分 |
| 错误执行率 | 已执行但结果错误 / 全部题目 | Chinook v0.8 S5：3/24，12.50% | 优先下降；高风险题允许用澄清或审批换取更低错误执行 |
| 覆盖率 | 给出可执行回答 / 全部题目 | Chinook v0.8 S5：23/24，95.83% | 与正确率一起报告，不能靠大量拒答抬高精度 |
| P95 延迟 | 95% 问题在该时间内完成 | Chinook v0.8 S5：14.39 秒 | 简单题和复杂题分别统计；审批等待时间单列 |
| 工具轮数与成本 | 每题工具调用、Token 和模型费用 | 已由评测框架记录 | 对每种运行路径设置预算和停止条件 |
| 安全通过率 | 危险写操作、越权、注入等被正确阻止的比例 | 已有 Governance/RLS 回归，并新增 Run 越权、竞态、拒绝不执行和脱敏测试 | 仍需真实认证和部署级安全集 |

上表的 24 题结果是历史本地开发证据，不是生产 SLA。v0.10.1 的 Chinook 100 题三轮业务正确率均值为 79.00%，生产候选门禁仍为 `NOT READY`；AdventureWorks 24 题三轮均值为 86.11%，只通过跨源回归门禁。两者都不能写成任意数据库的生产准确率保证。

### 在线产品指标

以下指标所需的 Run、反馈和审批事件已经能够采集，但当前尚无真实用户流量基线：

| 指标 | 计算方式 | 用途 |
| --- | --- | --- |
| 可信答案耗时 | 从提交问题到得到无需修改的答案 | 衡量真实效率，而非只看模型耗时 |
| 首次解决率 | 首次运行后用户标记正确 / 有反馈运行 | 衡量 Agent 是否减少反复沟通 |
| 澄清成功率 | 澄清后正确完成 / 发起澄清运行 | 判断 Agent 是否会问正确的问题 |
| 人工改判率 | 审批人修改或拒绝 / 全部审批 | 检查风险规则和模型判断是否合理 |
| 用户纠错率 | 被用户标记错误或部分正确 / 有反馈运行 | 发现离线题集未覆盖的问题 |
| 每个可信答案成本 | 总模型费用 / 正确且被接受答案 | 比单次调用成本更接近业务价值 |

## 数据源准确率准入

每个新数据源必须独立完成以下步骤，不能复用 AdventureWorks 或 Chinook 的分数：

1. 固定数据快照、Schema 快照和只读账号；
2. 由业务方确认核心指标、时间口径、粒度、允许 JOIN 和敏感字段；
3. 建立分层问题集，覆盖简单查询、聚合、时间、JOIN、窗口、空值、歧义和安全攻击；
4. 参考 SQL 在只读事务中验真；
5. 开发集用于改进，测试集用于版本准入，保留集只在候选版本冻结后使用；
6. 多次重复真实模型评测，并报告置信区间、错误执行、覆盖、延迟和成本；
7. 未达门槛时不静默放宽规则，选择修复、澄清、人工审批或不准入。

Chinook 100 题已按 `60/20/20` 划分开发集、测试集和保留集。其他数据源仍必须建立自己的分层题集和门槛，不能复制 Chinook 分数。

## 非目标

- 不为了体现“前沿”强行拆成多 Agent；现阶段一个有边界、可恢复、可审计的 Agent 更符合问题规模。
- 不把 LLM Reviewer 的同意当成业务正确证明；v0.6 已验证其成本更高且效果下降。
- 不让模型自行发明正式业务口径；指标合同由数据负责人确认。
- 不在没有可靠评测基线前做 Agentic RL。

## 证据边界

上游 QueryMind 已提供 Agent Loop、工具体系、SQL Governance、Schema Memory、RLS 基础和 FastAPI/Web Component。个人已完成模型与环境落地、多数据源隔离、评测框架、Query Plan、恢复实验和语义合同；v0.10 又实现了持久化运行状态、端到端脱敏 Trace、可暂停审批/澄清、反馈和质量准入。多实例存储、生产认证和真实在线 KPI 基线仍待部署验证。
