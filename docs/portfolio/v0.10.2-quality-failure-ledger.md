## 1. 阶段目标

在现有 `BenchmarkQualityAssessment` 上自动生成：

- 每题三轮中的稳定正确、稳定错误和波动状态；
- 稳定错误与波动样本 ID；
- development、test、holdout 分割集的业务正确率、wrong-but-executed 和重复一致性；
- 可供后续脚本直接使用的 JSON，以及供人工审计的 Markdown。

本阶段不优化运行时，不声称提高准确率。它只把原先散落在人工报告里的失败账本变成可重复生成的评测证据。

## 2. 先冻结的失败用例

先增加离线单元测试，固定下面的计算口径：

- 稳定错误：所有重复运行都为 `business_result_correct=false`；
- 稳定正确：所有重复运行都为 `business_result_correct=true`；
- 波动：重复运行中同时出现 true 和 false；
- split 业务正确率：该 split 全部运行样本中的正确比例；
- split wrong-but-executed：该 split 全部运行样本中“执行成功但业务错误”的比例；
- split 一致性：该 split 中非波动 case 的比例。

测试在实现前按预期失败：`BenchmarkQualityAssessment` 尚无 `stable_incorrect_case_ids` 字段。随后只扩展现有 assessment，没有新建第二套评测框架。
