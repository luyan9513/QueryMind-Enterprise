## 1. 结论

本阶段没有新建第二套 Agent、Query Plan、Semantic Contract、Governance 或 Evaluation
框架，而是在现有 `run_sql` 和 Run/Event 执行器之间补上确定性结果校验。只有最近一次
成功 SQL 的校验状态为 `passed`，Run 才能发出 `result.validated` 并进入 `succeeded`；
缺失、失败或无法确定的结果都会发出 `result.validation_failed`，并以稳定错误码进入
`failed`。

校验只使用接受后的 Query Plan、Semantic Contract 状态、列名、行数和可观察粒度，
不把 LLM Judge 当运行时权限判断，也不把结果行值写进事件证据。实现覆盖输出列数量与
顺序、机器列名/展示别名等价、空结果、计划上限、单值聚合、重复粒度和必需语义契约。

最终候选完成三轮 Chinook 100 题正式运行：业务正确率 84% / 82% / 84%，
wrong-but-executed 9% / 12% / 8%，三轮均值 83.33% / 9.67%。业务准确率和错误执行率
通过 profile；最差 P95 76.01 秒、一致性 84% 未通过，自动 admission 为 `NOT READY`。
此前被连接错误污染的 73/100 运行仍单独保留，没有混入聚合。

## 3. 失败用例先行与最小实现

### 3.1 先冻结的失败路径

- 已接受计划且列数量/顺序漂移时不能标记验证通过。
- 结果中出现重复计划粒度时不能标记验证通过。
- 计划预期有结果却返回零行时只能是 `inconclusive`。
- 超过计划 `limit`、无分组单值聚合返回多行、必需合同未通过时必须失败。
- Agent Run 没有成功 SQL 或没有校验证据时必须失败关闭，不能发 `result.validated`。

### 3.2 实现文件

| 文件 | 最小改动 |
|---|---|
| `src/QueryMind/core/agent/result_validation.py` | 新增无副作用的确定性校验器和脱敏元数据 |
| `src/QueryMind/core/agent/__init__.py` | 复用现有 Agent 包边界导出校验器 |
| `src/QueryMind/tools/run_sql.py` | 成功 SELECT 后附加 `result_validation`；失败时把修复信号交还现有 Agent Loop |
| `src/QueryMind/server/base/agent_run_executor.py` | 只对 `passed` 发 `result.validated`；其他状态发失败事件并关闭 Run |
| `tests/test_run_sql_and_summary.py` | 冻结列、别名、空结果、上限、聚合、粒度和合同用例 |
| `tests/test_agent_run_runtime.py` | 冻结 Run 成功与无证据失败关闭路径 |

运行时状态语义：

| 最近一次成功 SQL 证据 | 事件 | Run 结果 |
|---|---|---|
| `result_validation.status == passed` | `result.validated` | `succeeded` |
| 校验器缺失 | `result.validation_failed` | `failed / result_validation_missing` |
| `inconclusive` | `result.validation_failed` | `failed / result_validation_inconclusive` |
| `failed` | `result.validation_failed` | `failed / result_validation_failed` |

## 6. 费用、回退和剩余风险

本阶段所有可计量 DeepSeek 运行，包括失败候选、中断运行、定向复测、网络恢复 smoke
和三轮正式完整集，合计 **$0.799147**；加上 P0-B 的 `$1.302927` 后累计
**$2.102074**，低于用户批准的 `$5` 上限。

回退边界清楚：移除 `run_sql` 的校验元数据接入和执行器失败关闭即可恢复旧语义，不需要
修改冻结数据、参考 SQL、业务数据库或 Run Store。候选报告与负结果不删除。

剩余风险：

- 这是可观察结果结构校验，不证明业务值本身正确，也不取代 Benchmark 和人工审查。
- 展示别名等价只处理确定性的分隔符/括号形式，不做模型语义相似判断。
- 零行只能判为无法确定；没有足够业务先验时不能自动声称零行正确。
- 当前 Run Store 仍是单进程开发实现；本阶段不证明多实例、Exactly-once 或生产容量。
- 结果证据仍受 Chinook 冻结集、快照、模型和配置边界限制，不能外推任意数据库。
- 最差 P95 76.01 秒和一致性 84% 未过；P0-C 不按最终整合方案退出，也不进入 P0-D。
